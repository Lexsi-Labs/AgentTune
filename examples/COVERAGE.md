## Runs a real model on a GPU

The GPU-free studies inject a stand-in trainer, so they stop at the trainer boundary. Both real
training paths are exercised end-to-end on a GPU (weights actually update) under
[`examples/`](.):

- **SFT / distillation** — [`agentic_distillation_real.py`](agentic_distillation_real.py):
  `Project.distill(student, trainer_factory=...)` with a real `trainer_factory` that calls TRL's
  `SFTTrainer`. Teacher demonstrations → real SFT of `SmolLM2-360M` → the student learns a contract
  the base model doesn't follow (train_loss 3.60 → 0.25, verified before/after).
- **On-policy GRPO** — [`agentic_grpo_real.py`](agentic_grpo_real.py): agenttune's real
  `TrlAgenticGrpo` (TRL `GRPOTrainer`, LoRA) fine-tunes `SmolLM2-360M` with RL. Reward 0.03 → 0.66,
  contract rate 25% → 100%, correct-label rate 0% → 75% — the policy actually classifies, not a
  reward-hacked constant.
- **DPO (self-heal → preference RL)** — [`self_heal_dpo_real.py`](self_heal_dpo_real.py):
  the self-heal loop's corrective `{prompt, chosen, rejected}` data (via the spine's
  `build_dataset`) trains a real TRL `DPOTrainer` (LoRA). Reward accuracy 0.50 → 1.00, margin 1.97;
  the policy shifts off the failure behaviour. Closes the heal → train loop.
- **Reward-model training** — [`reward_model_real.py`](reward_model_real.py): trains the
  scalar scorer RL optimises against, with TRL's `RewardTrainer` (LoRA) on the same preference
  data. Mean chosen-minus-rejected margin +0.15 → +4.14 — the RM learns to score the correction
  above the failure.
- **RLOO (on-policy RL)** — [`rloo_real.py`](rloo_real.py): TRL `RLOOTrainer` (LoRA),
  leave-one-out baseline. Reward 0.03 → 0.70, contract 25% → 100%, correct-label 0% → 75% — within
  noise of GRPO, as expected for the same objective under a different advantage estimator.
- **BCO (binary-classifier preference)** — [`bco_real.py`](bco_real.py):
  `trl.experimental.bco.BCOTrainer` (LoRA) from unpaired feedback. Implicit reward margin +6.10;
  greedy output flips to the contract.
- **PPO (actor-critic RLHF)** — [`ppo_real.py`](ppo_real.py): trains a reward model, then
  runs the full `trl.experimental.ppo.PPOTrainer` (LoRA) actor-critic loop with a value model
  against it, end-to-end on the GPU. Honest scope: PPO is the most unstable of these at this scale
  — the short-run reward is noisy and doesn't reliably climb (a hotter LR drove it negative). The
  example verifies the pipeline *executes*, not that it converges.

- **Agentic-RAG GRPO** — [`rag_training_real.py`](rag_training_real.py): `RAGEnvironment`'s
  documented one-liner `create_agentic_trainer("grpo", tools=env.tools, reward_funcs=[env.reward])`
  run for real. Two library fixes make it work (the single-sample `env.reward` was silently scored
  `0.0` by TRL's batch call convention; `tools=env.tools` hit TRL's transformers≥5-only native tool
  path): `env.reward` is now dual-mode, and the GRPO backend auto-builds a tool-calling `rollout_func`
  from `tools` like RLOO already did. A live `Qwen2.5-3B` calls the real `search` tool during the GRPO
  rollout (16/16 completions searched and earned a real non-zero reward inside `train()`); scope is
  honest — pipeline executes with a real, search-driven reward, convergence not claimed (near-zero
  within-group variance on the toy corpus, like `ppo_real.py`).

- **RAG docs→QA data-gen + difficulty curriculum** — [`rag_datagen_real.py`](rag_datagen_real.py):
  `agenttune.rag.datagen`'s `generate_qa_from_corpus` and `label_difficulty` take LLM-backed callables
  (`generator`, `solver`) that were only ever exercised by mocks in `tests/rag/test_datagen.py`. This
  runs both over a real `Qwen2.5-3B`: it reads corpus chunks into grounded QA (6/6 gold chunks
  retrieved by the real BM25 retriever) and labels difficulty by probing the base model with no
  document. The corpus deliberately straddles the knowledge boundary — famous facts the model knows
  (→ easy) mixed with invented facts it cannot (→ hard) — so the probe discriminates (`easy=3/hard=3`)
  instead of collapsing to all-easy; the result is a real 1:1 balance + easy→hard curriculum whose
  generated hard pairs score non-zero through `env.reward`. Scope is honest: the *mechanism* runs for
  real; that auto-generated QA *trains well* stays an open bet, not claimed here.

- **LangGraph orchestrator → real GRPOTrainer** — [`langgraph_orchestrator_real.py`](langgraph_orchestrator_real.py):
  `AgentTuneGraph` composes a rollout node + LLM-judge nodes and documents `compile_rollout()` as
  drop-in `GRPOTrainer`-compatible. The only wiring into a real trainer (`e2e_test_suite.py::T11`)
  couldn't run here (hard-coded path, FP8 model) and scored training with a hand-written reward that
  read `completion.get("final_reward", 0.5)` off string completions — so it always returned the
  constant **0.5** and the graph's judges never scored the training completions. Root cause: the
  rollout output exposed judge results only as *batch-level* scalars, never a per-completion vector.
  A library fix keeps the judge node's per-trajectory scores and exposes a per-completion
  `judge_rewards` vector, plus a new `compile_grpo_reward()` reward_func that reads it. This example
  then runs the documented one-liner for real: a live `Qwen2.5-3B` tool agent is the rollout node,
  and two **divergent** `LLMJudge`s (a lenient answer-only rubric and a harsh show-your-work rubric)
  are mean-aggregated per completion — so the multi-node composition is observable (the judges diverge,
  a preflight asserts it) rather than a no-op. That non-constant judge reward (a real spread including
  partials like `0.75` — verified `≥2 distinct`, `max>0` so the judge genuinely parsed) drives a real
  GRPO LoRA `train()`. Scope is honest: a real, graph-composed judge reward drives a real
  `train()` (the constant stub never did); convergence is not claimed (within-group variance
  reported as-measured, like `ppo_real.py`).

- **Self-heal reward (TAC/TER)** — [`self_heal_reward_real.py`](self_heal_reward_real.py):
  the self-heal generator ranks synthesized corrections into `chosen`/`rejected` by
  `TAC (Tool Argument Correctness) + TER`, but `_process_single` scored a **mock trajectory**
  (the raw completion string shoved in as `tool_calls`), which `_calculate_tac` treats leniently
  and returns `1.0` for — so TAC could not tell a well-formed correction from a malformed one. A
  library fix parses the correction as JSON into a real `{name, arguments}` call and threads
  `tool_schemas` through the generator, so TAC validates the corrected arguments (valid `1.0` vs
  malformed `0.0`). Part 1 proves the discrimination deterministically (old raw path `1.0`/`1.0`
  vs fixed `1.0`/`0.0`); Part 2 runs the real generator end-to-end against a live `Qwen2.5-3B`,
  whose corrections are parsed and schema-scored through the fixed reward path. Scope: the reward
  is proven real and discriminating; the retrain-from-heal convergence lives in `self_heal_dpo_real`.

- **lm-eval standardized benchmarks** — [`lm_eval_real.py`](lm_eval_real.py): `LMEvalRunner`
  (the documented `agenttune.eval` integration with EleutherAI's `lm-eval`) had no test and no
  example — nothing ever shelled out to `lm_eval` and read a score back. This runs it for real: the
  real `lm_eval --model hf` CLI on a live `Qwen3-0.6B` over ARC-Challenge and WinoGrande (from the
  local HF cache, offline), and `LMEvalRunner` parses genuine accuracies from the results JSON and
  writes the combined summary. Scope is honest: the integration runs for real, but each task is
  capped at a small `--limit`, so the numbers are subset estimates, not full-benchmark scores.

**All seven trainers now execute genuinely on a GPU**: SFT/distill, GRPO, DPO, reward-model,
RLOO, BCO, PPO. Six show a clean learning signal; PPO runs end-to-end but needs far more
compute to converge (reported honestly). PPO and BCO import from `trl.experimental` in TRL 1.6
(the old top-level path raises AttributeError).

The trainers are the *training* surface. The *inference* surface is also exercised for real:

- **Real ReAct + agentic metrics** — [`agentic_strategy_real.py`](agentic_strategy_real.py):
  a live `SmolLM2-360M` **is** the `ReActStrategy` policy (not a scripted closure), driving
  `run_episode` over a real `DictToolHarness`, and `agentic_metrics` (tac/ter/arr/scsr/rad/lcf)
  scores the resulting *real* trajectories — the first time those metrics run off the
  `DemoRolloutEngine`. A `calc` tool lifts the same model from `answer_match` 1/6 → 5/6; the
  metrics are reported as an honest characterisation (e.g. `ter` is higher for the do-nothing
  arm), not a uniform scoreboard.
- **Real live-LLM self-heal** — [`self_heal_llm_real.py`](self_heal_llm_real.py): the
  litellm-bound heal stages run for real. `FailureClassifier` and `TrainingExampleGenerator` (via
  the real `as_sync_classifier` / `as_sync_generator` adapters and `SelfHealLoop`) make real
  `litellm.acompletion` calls to a local `Qwen2.5-3B-Instruct` — root-cause classification
  (`loop_collapse` 0.95, `wrong_tool` 1.0) and corrective `{chosen, rejected}` generation — then
  the loop's `trainer_factory` fires a real `DPOTrainer` to close detect→classify→generate→retrain
  end-to-end. The LLM is served locally because the sandbox is offline; production swaps
  `model_name` / `api_base` for a hosted endpoint and the heal path is unchanged. (This is why
  `as_sync_classifier` / `as_sync_generator` are no longer in the documented-not-run table above.)
- **DECIDE closed loop** — [`closed_loop_real.py`](closed_loop_real.py): the
  `FullClosedLoop` retrain→gate→deploy chain, whose model boundaries are stubs in every test, run
  for real. A real TRL `DPOTrainer` (LoRA) produces an adapter; the `DeploymentGate` decides on real
  task accuracy over a non-empty test set rebuilt from a real Decide audit log (old 0.33 → new 1.00,
  approved on merit); `deploy_trained_model` rewrites `config.yaml`; the deployed adapter is then
  reloaded as a real `PeftModel` — proof a real adapter was produced *and* deployed. (Focuses on the
  never-real retrain→gate→deploy chain; live detection is `self_heal_llm_real.py`.)

## Real components & transport (no GPU)

Three examples close gaps that were about a component only being exercised *in-process* or with an
offline stand-in — not a model gap. They run on CPU:

- **Service as a real server** — [`service_real.py`](service_real.py): the FastAPI
  `create_app()` operator surface, only ever tested via `TestClient`, is stood up under a real
  `uvicorn` server and driven over real `httpx` (every endpoint) plus a real `websockets` client
  (live event stream), with the operator UI fetched over HTTP. The server/transport/UI are proven
  real; the endpoints run the documented GPU-free control path. Standing it up also fixed a real
  WebSocket bug (idle client disconnects were never detected, leaking connections and logging a
  spurious shutdown traceback).
- **VectorMemory with a real embedder** — [`vector_memory_real.py`](vector_memory_real.py):
  `VectorMemory(embed=...)` with a real `sentence-transformers/all-MiniLM-L6-v2` instead of the
  bag-of-words stand-in. A paraphrase query with 0.04 lexical overlap is retrieved first, where a
  lexical baseline fails — semantic recall doing real work.
- **OpenEnvHarness against a real OpenEnv env** — [`openenv_harness_real.py`](openenv_harness_real.py):
  a genuine `openenv.core.Environment` subclass (real `Observation`/`Action` types, real `Rubric`
  reward) — an interactive higher/lower game — driven through `run_episode` + `run_conformance` +
  `replay`. Replaces the tests' hand-rolled `FakeEnv` with real `openenv` objects (a base
  dependency, no extra install needed).

Return-type classes (`AgenticEvalReport`, `AgenticMetrics`, `EvalReport`, `ConformanceReport`,
`HarnessCapabilities`, `LifecycleEvent`, `AgentState`, `Scope`, `MemoryKind`) are produced and
consumed by the covered calls above — they're exercised structurally, not named literally.
